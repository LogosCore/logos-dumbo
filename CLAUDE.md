# CLAUDE.md

`logos-dumbo` (`github.com/logoscore/logos-dumbo`): Dumbo, a Logos channel and factory in one repo and one image (`ghcr.io/logoscore/logos-dumbo`, both binaries; a `v*` tag publishes it), as `logos-ssh` is. Both are module `dumbo` with their own instance ids (`dumbo-local`, `dumbo-factory-local`). The factory builds PHP pages, `bind-call` minions; the channel (`cmd/dumbo-channel`, `internal/…`) carries only `bind-call`: core asks it over the control link to call a page, and it answers with what came back. A proof of concept: one target (`php-page`), eight commands (`hello` op 1, `download` op 2, `upload` op 3, `ls` op 4, `rm` op 5, `stream_download` op 6, `stream_upload` op 7, `walk` op 8). Replaces `logos-dumbo-channel` and `logos-dumbo-factory` (archived). README.md has the wire format, the schemas, what a page says and answers, config and management.

## Commands

```bash
go build ./... && go vet ./... && go test ./...
golangci-lint run --max-issues-per-linter 0 --max-same-issues 0 ./...
docker compose up -d --build
```

The page tests need `php` on `PATH` (they skip without it; `DUMBO_REQUIRE_PHP=1`, set in CI, makes them fail instead). CI (`.github/workflows/ci.yml`, the other Go modules' file plus a PHP check) runs the tests and golangci-lint v2.13.2 with default linters, no config: keep 0 issues (an explicit `_ =` with the reason for a Close whose error says nothing).

## The channel

- `cmd/dumbo-channel/main.go`: config, logging (module-core `logging.New` teed into a `logstream.Hub`), the caller, management, the control-plane session (channel-core `channel.Run` with the connection schema) and the control link (channel-core `linkclient.Run`, `Handler: caller.Call`, `OnState: caller.SetLinkUp`). Shutdown: drain, close the link once calls in progress end (at most `CALL_TIMEOUT` + 5s), then deregister. Embeds `icon.svg` (dark themes: the filled figure, lines cut out) and `icon-light.svg` (light themes: the lines), traced from a line drawing of a sitting baby elephant; a test validates both.
- `internal/connection`: the connection schema, one kind, `bind-call`: `method` built in (POST, PUT, PATCH); target fields `url`, `host_header`, `proxy`, `tls_verify`, `user_agent`, `headers`. `Version` covers the built-in fields only. Every field has a number, as every channel's must (docs: minion-connection, Field numbers), one numbering for the fields and the targets': `method` 1, then the targets' 2 to 7 in that order; a number stays its field's (`TestFieldNumbers`).
- `internal/caller`: makes a call: body `id(16) ‖ sealed frame`, `application/octet-stream`, the target's method and headers. A `200` octet-stream answer at least `16 + protocol.MinFrameSize` long is the page's (id and frame to core, never read here); any other response is "not the minion" (status and a 512-byte excerpt); no response is a failure, classed `unreachable` / `timeout` / `tls` / `other`. Transports are kept per proxy and TLS setting (at most 64). Counters and the link state feed management.
- `internal/management`: properties `call_timeout`, `max_body_bytes`, `log_level` (all live), actions `drain`/`resume`, status counters. How the channel reaches core stays env-only.
- `internal/config`: env config (`CHANNEL_ID`, `LOGOS_CORE_BASE_URL`, `CALL_TIMEOUT`, `MAX_BODY_BYTES`, `LOG_FORMAT`, `RABBITMQ_*`).

## The factory (`cmd/dumbo-factory`)

- `main.go`: factory-core `factory.Run` with the build schema, the builder and management; embeds `icon.svg` / `icon-light.svg` (the Dumbo channel's elephant).
- `build.go`: the build schema (version 1: channel `dumbo` v1, its `num` 1, kind `bind-call` with no factory fields; crypto `aes-256-cbc-hmac-sha256`; field `greeting` (`num` 1, as every field must have one); target `php-page`, `any/any`; commands `hello`, `download` (`download_file`), `upload` (`upload_file`), `ls` (`list_dir`), `rm` (`delete_path`), `stream_download` (`stream_file`), `stream_upload` (`upload_stream`), `walk` (`walk_dir`)) and the builder (steps render, upload). `render` fills `page.php`'s placeholders (`__BUILD_ID__`, `__ID8__`, `__METHOD__`, `__ENC_KEY__`, `__MAC_KEY__`, `__CONN__`, `__GREETING__`, `__VERSION__`, and the answer sizes `__CHUNK__`, `__WALK_BYTES__`, `__MAX_ENTRIES__`, `__PIECE__`); the page answers the build's first bind-call connection through the Dumbo channel, its method from the endpoint's `method` (POST, PUT, PATCH; POST by default).
- `page.php`: the minion, a template embedded in the binary. Plain PHP 7.0+ with openssl: the sealed frame (AES-256-CBC, HMAC-SHA256 over id ‖ body), a CBOR subset (byte strings as `DumboBytes…`, protocol maps as `DumboMap…`: a PHP array with keys 0, 1, 2… would encode as an array), rehello → hello, tasks run in the call (ack + result), files a chunk a call (512 KiB) with what the page needs in the transfer's `ctx` (protocol v0.25.0, core echoes it: kind, path, task, size; an upload's `.part` file and SHA-256), cancels: a walk stops where its ctx says, an upload's partial file is removed and the task ends `stopped: N bytes had come` (core's cancel carries the transfer's ctx when the task has none), a download ends `stopped`; anything else → `unknown_task` naming the task (key 4), which core ends, other items → `unknown_item`, `get_tasks` max 4 in every answer, and a plain 404 for anything else. Every call must say core's time (`at`, message key 4) within 10 minutes of the page's clock (`STALE_WINDOW`, `protocol.StaleWindow`): otherwise nothing in it runs and the page answers only `err` `stale` (7) with its time, a replay or a clock that is off. An `err` from core that carries an upload's `ctx` (core echoes the ctx of the item an err is about) removes its `.part` file. What one answer carries is sized from the connection's `max_message` at render (`pageConn.sizes`: `__CHUNK__`, `__WALK_BYTES__`, `__MAX_ENTRIES__`, `__PIECE__`; over the protocol's limit 512 KiB, 600 000, 5000, 500). Class names carry the build id's first 8 hex digits so two pages never clash. `OP_HELLO`, `OP_DOWNLOAD`, `OP_UPLOAD`, `OP_LS`, `OP_RM`, `OP_STREAM_DOWNLOAD`, `OP_STREAM_UPLOAD`, `OP_WALK` must match the schema's ops (a test checks).
- `management.go`: `log_level` only; factory-core adds the builds section.
- `build_test.go`: the schema, the manifest and the icons; builds through `factorytest` (placeholders filled and escaped, failures `bad_method`, `no_keys`, `no_bind_connection`). `page_test.go`: the rendered page under `php -S`, spoken to with the protocol package as core speaks to it; `transfer_test.go`: downloads and uploads through it, the test echoing `ctx` as core does; `files_test.go`: `ls` and `rm`; `stream_test.go`: both streams, the test holding them and letting them go with unasked acks as core does; `walk_test.go`: a walk too big for one answer, resumed across calls as core does, and one stopped by a cancel with its ctx.
- `channel_test.go`: the two halves together: the channel's `caller` calls a page built here, under real PHP; the page's answer is the caller's (200, octet stream, id and frame), anything else not the minion. The contract between `page.php` and `internal/caller` is this test: a change to either side runs it.

## Conventions

- The channel is plaintext-blind: it never opens, reads or logs a frame. Logs carry the request id, the URL, the outcome, the status and the duration.
- Lifecycle, management serving and the control link's plumbing stay in module-core and channel-core; this repo only makes calls and declares what is managed.
- `www/` is for trying pages locally (served by the `dumbo-www` compose service); its contents are gitignored.
- Key material goes into the page and nowhere else: never logged or in progress.
- A change to what the page reads or answers is a change to the minion: run the page tests (tested on PHP 7.0, 7.4, 8.3, 8.4).
